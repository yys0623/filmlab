# v3 색역 경계 개선판 검증

## 변경 범위

개선판은 보존 v3의 원래 필름/LUT 처리, 중성색 제거, 명도 제한, chroma gain을 유지한다. 마지막 sRGB 색역 매핑만 바꾼다. 기존 v3, A/B, V-Log 원본은 비교용으로 유지한다. 실제 필름·인화지·카메라의 실측 정확도를 새로 주장하지 않는다.

원래 v3의 경계 매핑은 색역 밖의 chroma를 같은 L/h의 경계에 모으므로, 경계를 넘어선 서로 다른 색의 radial chroma 구분이 줄어들 수 있다. 개선판은 그 경계 직전부터 부드럽게 압축한다. 이미 유효한 색역 안의 경계 부근에도 영향이 있으며, 사진별 자동 통계나 노출 조정은 없다.

고정 OKLab L과 색상각 h에서 중성축과 연결된 첫 sRGB 경계를 `Cmax`라 정의하고 `r=C/Cmax`를 사용한다.

```
r <= k: f(r) = r
r >  k: f(r) = k + (1-k)(r-k)/(r-k+1-k)
Cout = Cmax * f(r)
```

기본값 `k=0.90`은 모든 조합에 공통이다. r=k에서 함수값과 1차 미분은 identity와 일치한다. 그 뒤 미분은 `(1-k)^2/(r+1-2k)^2 > 0`이다. 따라서 **고정 L/h의 r 방향**에서 C1 단조이며 경계에 점근한다. 모든 L/h 방향에서의 전역 C1 연속성을 증명한 것은 아니다.

r=1에서 chroma는 `(1+k)/2`배가 된다. k=.85/.90/.95는 첫 경계에서 각각 7.5%/5%/2.5% 감소한다. r≤k는 바꾸지 않는다. 뒤쪽의 분리된 색역 재진입 구간은 r>1일 수 있으므로, **이미 sRGB 안에 있던 모든 색의 감소를 5% 이하로 보장하지는 않는다.** 8비트 반올림과 33³ 보간 후 채널 경계값이 완전히 없어지는 것도 보장하지 않는다.

## 파랑 경계의 재진입 처리

독립 검사 중 파랑 일부의 OKLab 고정 L/h 광선이 sRGB에서 이탈한 뒤 재진입하는 것을 확인했다. 예를 들어 실제 Velvia 입력 [2,36,108]/255의 v3 pre-gamut 값은 대략 `[.32352043,-.01999264,-.19493118]`이다. 단순 이분법은 탐색 상한에 따라 첫 경계 대신 더 뒤쪽 경계를 선택할 수 있다.

최종 구현은 각 RGB 채널의 cubic(t)를 구성하고, 세 채널의 모든 실수 도함수 근으로 탐색 구간을 분할한다. 각 구간에서 모든 채널이 단조이므로, 처음 범위 밖인 구간만 골라 24회 이분법을 수행한다. 단순히 끝점 하나가 색역 안인지 검사해 재진입을 놓치지 않는다. 최종 LUT는 이 수정 후 다시 생성한 것을 사용한다.

독립 참조는 상대 scale 대신 절대 chroma에서 critical-point 구간을 구성하고 27회 이분법으로 첫 경계를 찾았다. 별도로 `numpy.roots`를 사용해 RGB=0/1 cubic의 양의 실근과 대조했다.

| --- | --- |
| 601개 광선의 독립 첫 경계 vs 직접 cubic 근 | 최대 chroma 오차 3.69e-9 |
| 31개 광선 × 2,001 chroma 좌표, r=0–10 | 1e-8보다 큰 chroma 역전 0, 유한 범위 출력 |
| 1,000개 픽셀 순서 변경 | RGB 차이 0 |

Velvia에는 첫 경계 뒤 재진입 구간에 놓인 실제 입력이 36개(0.0251%) 있었다. 다른 세 조합에는 없었다. 그래서 5% 감소 한계의 적용 범위를 첫 연결 경계라고 명시했다.

대표 4개 crop을 원본/v3/k=.85/.90/.95로 비교했다. k=.9는 기존 강한 색의 인상을 대체로 유지하고 경계 부근을 조금 완화한다. crop만으로 원래 사진에 없던 디테일이 복구됐다거나 실제 필름에 더 정확해졌다고 판단하지 않는다. k=.85는 더 많이 변화하고, k=.95는 일부 채널 경계가 더 남으므로 .9를 공통 절충값으로 선택했다.

### 연속 L/h 고정과 33³ 보간의 구별

정확한 연속 매핑은 L/h를 고정한다. 최종 LUT는 각 격자점의 RGB를 보간하므로, 곡선적인 OKLab 공간에서 같은 성질을 정확히 유지하지는 않는다.

- 전238 표본에서 실제 v3/개선 CUBE의 최대 L 차이는 .002011이었다. Reala Ace Direct, 원본 RGB [0,0,4]/255인 매우 어두운 픽셀에서 발생했다. 조합별 p99 중 가장 큰 값은 .00029195였다.
- 양쪽 C>.02, L>.1인 픽셀의 최대 색상각 차이는 4.7149°였다. Reala Ace Direct, 원본 [1,4,7]/255에서 발생했다. 조합별 p99 중 가장 큰 값은 .49433°였다.
- 회색은 전238에서 보간 후에도 정확히 같은 RGB였다.

이 때문에 최종 CUBE까지 모든 유채색 픽셀의 L/h가 수학적으로 완전히 동일하다고 표현하지 않는다. 매우 어두운 색에서는 작은 RGB 변화도 비교적 큰 색상각 차이로 표시될 수 있다.

### 실제 앱 및 다운로드 검증

실제 브라우저에서 Classic Chrome / Crystal Archive Type II의 `0202STR.cube`를 다운로드하고, S5II 샘플 1067×1600 렌더 PNG에 대해 독립 CUBE reader/tetrahedral 적용 결과와 비교했다. 다운로드 SHA가 manifest와 일치했고, RGB 픽셀 100% 동일, 평균·최대 8비트 채널 오차 0이었다. 근거는 `artifacts/v3-refined-browser/independent-preview.json`이다. 통합 검사에서 JS 51개, JPG Python 26개와 exporter Python 8개 테스트 및 빌드가 통과했다.

- `artifacts/v3-refined-review/pilot.py`, `pilot.json`: 4조합, 35사진, k 세 값의 연속 비교.

- `artifacts/v3-refined-review/all-cubes.json`, `all-cubes-summary.json`: 최종238개·모든 필름쌍·그룹·최저 장면의 독립 감사 결과.
