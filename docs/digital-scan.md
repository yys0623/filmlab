# 인화지 없는 네거티브 디지털 스캔

> 현재 STD 입력은 [카메라별 STD→V-Log 변환](camera-std.md)을 사용합니다. 아래 B·JPG 톤 보호 설명은 변경 이력이며, V-Log 룩과 인화 모델 설명은 그대로 적용됩니다.


## 이전 STD v3 · JPG 톤 보호 — 2026-11-03

네거티브 디지털 16종의 STD는 아래의 고정 양화 모델 뒤에 `pipeline/jpg.py`의 `film-lab-jpg-tone-protection-v1`을 추가한다. 이전 결과의 들린 갈색 블랙과 눌린 밝은 영역을 그대로 최종 JPG 톤으로 사용하지 않는다. 각 룩의 회색 4,097개 응답을 한 번 계산해 같은 입력 휘도의 중성 응답을 참조하며, 디지털 모드의 **중성 톤 잔류 계수는 0**이다. 이는 LUT 강도 0%가 아니라 중성 톤 보상 계수이며 색상 모델은 계속 사용한다.

모델 출력의 밝기를 원본 OKLab L 주변의 부드러운 범위로 제한하고, 중성 색편향을 제거한다. sRGB 밖의 색은 밝기·색상 방향을 유지하며 채도를 줄인다. 검정·흰색 끝점은 정확히 보존하고 사진별 노출·화이트밸런스·공간 필터는 적용하지 않는다. 수식과 범위는 [README의 JPG 톤 보호 계약](../README.md#jpg-톤-보호-v3), 실제 계수는 `pipeline/jpg.py`의 metadata에 기록한다.

보호는 STD 생성 단계에 포함되어 샘플·업로드 미리보기·다운로드가 같은 STD LUT를 사용한다. 원본 사진과 V-Log 파일은 이 보정의 대상이 아니다. 카메라의 비공개 렌더링을 역변환하거나 실제 스캐너와 일치시킨 보정이 아니며, 원본에서 사라진 디테일은 복원하지 않는다.

아래 지원 수량·초기 검증 수치와 블랙 레벨 설명은 **디지털 모드 도입 당시의 기반 모델 기록**이다. 기반 모델과 V-Log 계약은 유지하지만, 현재 STD v3의 최종 응답·보간 오차·파일 해시를 이 과거 수치로 대신하지 않는다. 최신 결과는 조합별 QA와 검증 기록을 따른다.

## 지원 범위 (도입 당시)

네거티브 16종에 `디지털 스캔`을 추가한다. 기존 인화지 8종의 128개 조합과 슬라이드 4종의 직접 스캔은 유지한다. 총 **148개 룩, 296개 LUT, 148개 ZIP, 888개 미리보기**다. 각 디지털 룩의 ID는 `<film>__digital_scan`, `processMode`는 `negative_digital`, `paper`는 `null`이다.

이 모드는 **Film Lab에서 추가한 실험적 네거티브 양화 모델**이다. spektrafilm 원작자의 공식 인화 출력이나 특정 상용 스캐너를 재현했다고 주장하지 않는다. 필름 노광·현상은 고정된 upstream 0.3.4를 사용하고, 그 뒤의 가상 RGB 스캔·양화 변환을 `pipeline/digital.py`에서 구현한다. 슬라이드는 기존 `positive_direct` 경로를 유지한다.

## 고정된 변환

모델 ID는 `film-lab-common-digital-negative-v1`이다. 모든 네거티브에 같은 가상 광원·센서·감마·톤 함수를 적용한다.

| 항목 | 값 |
|---|---|
| 스캔 광원 | D50 |
| Gaussian RGB 센서 중심 | 620 / 540 / 460 nm |
| 센서 표준편차 σ | 35 / 30 / 25 nm |
| 공통 역농도 감마 | 0.60 |
| 회색 기준 선형 RGB | 0.184 |
| 공통 채널 톤 함수 | `q / (0.816 + q)` |
| 출력 | upstream CAM16-UCS gamut compression → sRGB encoding → 0–1 경계 |

Gaussian 센서는 실측 스캐너 감도 자료가 아니다. 보정된 장치 행렬 없이 이 가상 RGB를 선형 sRGB로 해석하는 모델이며, 위 계수는 Film Lab의 공통 렌더링 선택이다. 실제 스캐너의 색 측정값 또는 필름별 측정 감마로 해석하면 안 된다.

1. upstream을 `cmy_film`까지 실행해 해당 필름의 CMY 현상 농도 `d`를 얻는다. 필름의 감도, 특성곡선, 염료 데이터와 DIR coupler를 사용한다.
2. 필름의 염료 스펙트럼 `A`와 베이스 농도 `B`로 `Dλ = Bλ + Σk d_k Aλk`를 계산한다. 채널별 스캔 신호는 `S_c = Σλ D50λ G_cλ 10^(-Dλ)`다. 센서 가중치는 채널별 합이 1이 되도록 정규화한다.
3. CMY 현상 농도가 0일 때의 동일 필름 베이스 신호 `S_base`로 나누고 `D_c = -log10(S_c / S_base,c)`를 계산한다. 이것은 가상 RGB 채널별 베이스 보정이며, 실제 스캐너의 오렌지 마스크 제거를 교정한 결과는 아니다.
4. 같은 필름에 선형 RGB `(0.184, 0.184, 0.184)`를 입력해 고정 회색 농도 `D_gray`를 얻는다. `q_c = 0.184 × 10^((D_c - D_gray,c) / 0.60)`으로 양화한다.
5. 모든 필름·채널에 같은 `q / (0.816 + q)`를 적용한 뒤 출력 gamut compression과 sRGB encoding을 수행한다. 이 톤 함수는 기준 회색의 0.184를 유지하면서 밝은 값을 부드럽게 제한한다.

프로필에 없는 파장대의 NaN 투과량은 upstream `density_to_light`와 동일하게 0으로 처리하며 스펙트럼을 임의로 연장하지 않는다. 베이스 기준에도 동일한 파장 마스크를 사용한다. 베이스 대비 투과량이 1을 넘는 경우의 부호 있는 농도는 유지하며, 로그 안정성을 위한 하한 `1e-30`만 둔다.

필름별로 다른 것은 원본 필름 데이터와 고정 회색 농도 오프셋이다. 필름별 기울기 맞춤, 색 행렬 맞춤, 이미지 통계, 자동 노출, 필름 이름별 추가 채도·색조 값은 사용하지 않는다. 회색 균형을 맞추므로 일부 색 차이는 여전히 작을 수 있다. 인화지 모델을 제거했다고 실제 필름 고유색이 완전히 분리되거나 측정된다는 뜻은 아니다.

공통 톤은 암부를 이미지별로 검정까지 늘이지 않는다. 16종의 회색 램프에서 선형 입력 `1e-5`의 출력 밝기는 encoded RGB 가중합 기준 약 **26–35/255**, 입력 10에서는 약 **214–224/255**였다. 따라서 검정이 약간 들리고 밝은 영역이 눌린 결과가 나올 수 있다. 원본 곡선의 toe 구간에는 최대 약 **0.0183/255**의 작은 역방향 변화가 있어, 엄밀한 전 구간 단조 증가를 주장하지 않는다. 이 응답을 보존하며 별도의 검정점 늘이기나 곡선 교정은 하지 않았다.

## 실행 경로와 내보내기

토폴로지는 `preprocess → filming.expose → filming.develop → scanning.digital_negative`다. 인화지 노광·현상·인화 스캔 노드는 실행하지 않는다. upstream 초기화에는 인화지 객체가 필요해 내부적으로 Portra Endura를 로드하지만, 이 객체는 디지털 결과에 적용하지 않는다. 초기화 객체를 Crystal Archive로 바꿔도 결과가 같음을 검사한다.

V-Log 파일은 V-Log/V-Gamut 입력을, STD 파일은 기존의 sRGB 근사 입력을 받으며 모두 sRGB를 출력한다. STD는 중간 V-Log LUT를 보간하지 않고 연속 모델을 STD 격자에서 직접 계산한다. 선형 입력 배율은 1.0이다. 카메라의 비공개 Standard 렌더링·화이트밸런스·클리핑을 역변환하지 않는다.

프로덕션에서는 기존 조합별 ZIP 한 벌을 전송에 사용한다. manifest의 `encoding: "zip-entry"`가 선택한 LUT의 ZIP 내부 경로를 지정하며, 브라우저는 ZIP의 크기·SHA-256을 확인하고 `.cube`를 무손실 압축 해제한 뒤 원본 LUT의 크기·SHA-256도 확인한다. 검증한 파일을 개별 다운로드와 내 사진 미리보기에 사용한다. 개별 LUT의 별도 raw/gzip 전송 사본은 배포에서 생략하지만, 로컬 `public/`의 원본 `.cube`와 ZIP은 바뀌지 않는다. 이 방식은 인화·디지털·슬라이드에 공통으로 적용하며 색 변환 수치나 이미지 품질에 영향을 주지 않는다.

기존 룩을 다시 만들지 않고 새 디지털 자산만 추가하려면 다음을 실행한다.

```bash
.venv/bin/python -m pipeline.generate --digital-only --jobs 3
```

이 명령은 엔진과 STD 어댑터가 기존 카탈로그와 같은지, 기존 파일의 해시가 일치하는지 확인한 뒤 기존 인화·슬라이드 레코드를 보존한다. `--force`는 선택된 디지털 룩만 재생성한다. 전체 `pipeline.generate` 실행은 모든 모드의 캐시를 점검한다.

## 검증과 한계

새 16개 조합은 모두 `ready`, 실패·검토 경고는 0개다. 조합마다 고정 시드의 4,350개 입력에서 최종 LUT와 연속 디지털 모델을 비교했다. 사면체 보간의 조합별 최악 p99는 V-Log **0.008682**, STD **0.001528**이다. 단위는 encoded sRGB 0–1의 최대 채널 절대 오차다. `qa.referenceModel`에 Film Lab 모델 ID를 기록해 원본 인화 엔진 QA와 구분한다.

`test_digital.py`는 16개 필름의 양화 방향·유한 출력·회색 기준, 인화 노드 미실행, 초기화 인화지 독립성, 이미지 내용과 무관한 픽셀 변환, 필름 프로필 구분, 메타데이터와 보간을 검사한다. `test_digital_reference.py`는 Portra 400·C200·Vision3 500T를 별도로 초기화한 upstream 런타임에서 CMY까지 현상한 뒤, 제품의 스캔/양화 helper를 사용하지 않고 파장별 합과 공통 변환식을 직접 계산한다. 각 필름의 무작위·경계·회색 입력 1,180개에 대해 제품 연속 모델과 절대 오차 `2e-6` 이내 일치를 검사했다.

추가 전후 **기존 132개 룩의 1,980개 파일 전체 SHA-256이 같다**. 여기에는 기존 LUT 264개, 미리보기 792개, ZIP·QA·provenance·metadata가 포함된다. 디지털 16종의 STD와 V-Log 해시는 각각 모두 다르며 프로필 ID도 카탈로그와 일치한다. 로컬 검증 근거는 `artifacts/digital-baseline.json`과 `artifacts/digital-preservation-verification.json`이다.

이 검증은 선언한 가상 모델의 구현·재현성·독립성을 확인한다. 실제 필름 촬영과 현상, 상용 스캐너, 카메라 내부 Real Time LUT와의 색 일치는 검증하지 않았다. 사용자 소유 놀이터·실내 피규어 사진의 인화/디지털 비교는 같은 STD 파일을 독립 LUT reader로 적용한 예시다. 다른 카메라 5종의 외부 샘플 갤러리는 로컬 전용으로 유지하며 이번 배포 자산에 포함하지 않는다.

ZIP 전송 변경 전 디지털 모드 구현 검증에서 전체 Python 테스트 **68개**, JavaScript 테스트 **10개**가 통과했다. 브라우저에서 사용자 사진 업로드, 인화/디지털 전환, 디지털 STD 다운로드와 카탈로그 해시 일치를 확인했다. 기존 인화/슬라이드 자산 보존 검사는 생성 완료 후 다시 수행했다. 배포 전송 관련 검증은 [검증 기록](validation.md)에 구분해 기록한다.
