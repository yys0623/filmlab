# 인화 필터 미세 조정 (실험)

spektrafilm GUI의 **Print M filter shift / Print Y filter shift**를 웹에서 슬라이더로 조절합니다. 데이터베이스 중립 필터에 Kodak CC 단위로 더하는 값이며, 암실에서 인화 기사가 컬러 타이밍을 잡는 조작과 같습니다.

- 그 필터를 더 넣으면(+) 그 색이 빠집니다. M+는 초록 쪽, Y+는 파랑 쪽, M−는 마젠타 쪽, Y−는 노랑 쪽입니다.
- 범위는 M·Y 각각 −30 ~ +30 CC, 1 CC 단위입니다.
- 슬라이더는 선택한 룩을 기준으로 움직입니다. "필름 색 남김"을 고른 상태라면, 그 변형의 혼합 필터(기본 중립 필터에서의 이동량)에 슬라이더 값을 더합니다. 합계도 ±30 CC 안으로 제한합니다.
- 두 슬라이더가 모두 0이면 기존에 배포한 LUT 파일을 그대로 씁니다.

## 왜 LUT를 나눠 굽나

필터는 파장별로 작용해서, 완성된 LUT 뒤에 채널별 상수를 더하는 방식으로는 재현되지 않습니다. 실측에서 ±20 CC 이상이면 8비트 기준 오차가 17~39까지 커졌습니다. 그래서 인화지 노출 지점에서 체인을 나눕니다.

```
A(m, y): V-Log RGB → 인화지 log10 노출   (필름 노출·현상, 확대기 중립 필터 + 이동)
B:       인화지 log10 노출 → sRGB         (인화지 현상 + 스캔, 필터와 무관)
```

A는 (M, Y) = {−30, 0, +30}²의 9개 지점에서 굽고, 그 사이는 2차(라그랑주) 보간으로 섞습니다. 엔진 직접 계산과 비교한 보간 오차는 8비트 기준 최대 약 0.4입니다. 브라우저는 슬라이더 값마다 `STD → 카메라 변환(삼선형) → ΣwA(사면체) → B(사면체)`를 33³ 큐브 하나로 합성해 미리보기와 다운로드에 씁니다.

## 파일

- `public/print-timing/<기본 룩 ID>.bin`: 인화 조합(네거티브 16 × 인화지 8 = 128개)마다 하나, 약 2.2 MB.
- 형식: `SFPT1\n`, 헤더 길이(u32), JSON 헤더, uint16(값/65535) 표 10개(A[m][y] 9개, B). 표는 `.cube` 행 순서(R이 가장 빠름)입니다.
- 카탈로그 `printTiming`에 방식, 범위, 보간, 각 팩의 해시와 QA를 기록합니다. `npm run verify:assets`가 팩 해시, 헤더, 기본 VLOG 해시, QA 한도를 확인합니다.

## 정확도

각 팩은 생성할 때 (0, 0), (−15, +15), (+15, −15), (−7, +3), (+25, +25)에서 엔진 직접 계산과 비교합니다. C200 + Crystal Archive 기준으로 8비트 평균 오차는 약 0.6, p99는 약 3으로, 지금 배포 중인 단일 LUT 자체의 오차와 같은 수준입니다. p99가 0.03(8비트 약 7.7)을 넘으면 생성을 중단합니다.

## 한계

- 미리 구운 지점 사이를 보간하는 근사입니다. 정확한 값은 spektrafilm GUI에서 같은 shift로 확인할 수 있습니다.
- 다운로드는 STD와 V-Log 큐브만 지원합니다. ZIP(생성 정보와 QA 포함)은 기본값(0, 0)에서만 받을 수 있습니다.
- 그레인, 할레이션 같은 공간 효과는 다른 LUT와 마찬가지로 포함하지 않습니다.
