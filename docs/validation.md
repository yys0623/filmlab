## 2026-11-03 — FUJI JPG 암부 압축 수정 v2

이 수정은 Film Lab의 디지털 입력·인화 연결을 개선한 것이다. 실제 카메라 역프로파일 또는 실물 인화의 계측 보정은 아니다. 원본에서 이미 손실된 정보를 복원하지 않으며, Velvia 등 시뮬레이션 고유의 강한 대비와 재료의 색편향은 남는다.

## 프로덕션 ZIP 전송

디지털 룩 추가로 커진 배포 파일을 줄이기 위해 프로덕션 LUT 전송은 기존 조합별 ZIP을 재사용한다. 148개 ZIP에 담긴 296개 LUT를 `encoding: "zip-entry"`로 참조하며, 배포 폴더에는 개별 LUT의 별도 raw/gzip 전송 사본을 두지 않는다. 브라우저는 전송받은 ZIP의 크기·SHA-256과 추출한 `.cube`의 원본 크기·SHA-256을 각각 검사한다. 개별 V-Log/STD 다운로드와 업로드 사진 미리보기는 이 검증된 원본 바이트를 사용한다. 묶음 ZIP 다운로드도 유지한다.

이 변경은 무손실 전송·배포 구성에만 적용한다. 로컬 `public/`의 원본 `.cube`, ZIP, 카탈로그 원본 해시와 이미지 자산은 유지한다. LUT의 수치 정밀도나 이미지 품질을 낮추지 않는다. 아래 이전 기록의 gzip 전송은 당시 구현 이력이며 현재 프로덕션은 ZIP 내부 항목을 추출한다. ZIP 전송 검증에는 압축 파일의 무결성, 지정 항목 추출, 추출한 LUT의 원본 일치 여부가 포함된다.

최종 JavaScript 검사 **14개**가 통과했고, 변경되지 않은 색 변환의 Python 검사 **68개**도 통과했다. 배포 폴더의 296개 LUT와 1,628개 참조 자산을 검증했다. 별도의 Python `zipfile`로 배포 ZIP에서 296개 LUT를 추출해 카탈로그의 원본 크기·SHA-256과 모두 일치함을 확인했다. 프로덕션 미리보기 브라우저에서 ZIP 기반 업로드 사진 렌더링과 `0167STD.cube` 개별 다운로드를 확인했으며, 내려받은 파일은 원본과 바이트가 같다. 검증 기록은 `artifacts/digital-zip-verification.json`에 있다.

## 네거티브 디지털 스캔 추가

인화지를 사용하지 않는 `negative_digital` 16개를 추가했다. 전체는 **148개 ready / 실패 0개**, **296개 LUT / 148개 ZIP / 888개 미리보기**다. 신규 경로는 upstream 필름 노광·현상 다음에 Film Lab의 공통 가상 RGB 스캔·양화 모델을 실행한다. 모델 ID는 `film-lab-common-digital-negative-v1`이며, 상용 스캐너나 원작자의 공식 출력과 일치한다고 주장하지 않는다. 수식·고정 계수·입력 한계는 [디지털 스캔 기록](digital-scan.md)에 있다.

신규 16개 조합 모두 검토 경고 0개다. 4,350개 입력의 직접 연속 모델 대비 사면체 보간에서 조합별 가장 큰 p99는 V-Log **0.008682**, STD **0.001528**이다. 단위는 encoded sRGB 0–1의 최대 채널 절대 오차다. QA의 `referenceModel`로 이 Film Lab 확장 모델을 구분한다.

독립 파장 적분 테스트 3개가 통과했다. Portra 400·C200·Vision3 500T 각각의 1,180개 무작위·경계·회색 입력에서, 제품의 스캔/양화 helper 없이 upstream CMY 현상 결과부터 별도로 계산한 출력과 절대 오차 `2e-6` 이내로 일치했다. 이는 선언한 가상 변환의 구현 검증이며 실물 색 측정은 아니다. 16종의 STD/V-Log 해시는 각각 고유하고 카탈로그·provenance의 필름 ID가 일치한다.

디지털 모드 추가 전후 **기존 인화·슬라이드 132개 룩의 1,980개 파일 전부 바이트가 같다**. LUT 264개, 미리보기 792개와 ZIP·QA·provenance·metadata를 포함한다. 보존 근거는 `artifacts/digital-baseline.json`, 확인 결과는 `artifacts/digital-preservation-verification.json`이다. 5개 카메라의 외부 촬영 샘플 갤러리는 로컬 전용으로 유지했다.

ZIP 전송 변경 전 디지털 모드 구현 검증에서 전체 Python 테스트 **68개**, JavaScript 테스트 **10개**가 통과했다. 브라우저에서 사용자 사진 업로드, 인화/디지털 모드 전환, 디지털 STD 다운로드와 파일 해시 일치를 확인했다. 새 디지털 모드는 공통 톤의 유한 암부 바닥과 하이라이트 압축을 가지며 이미지별 검정점 늘이기는 하지 않는다. 세부 응답과 작은 toe 역방향 변화는 디지털 스캔 기록에 명시했다.

아래 STD v2 및 슬라이드 지원 기록의 132개/264개 수치는 당시 자산 수이며, 현재 지원 수는 이 절의 148개/296개다.

## STD 직접 엔진 생성 v2 — 인화·슬라이드 검증

색감 재검토 결과, 필름 프로파일 재사용이나 필름 선택 누락은 발견하지 않았다. 동일 인화지의 유사성은 원본 엔진에서도 재현되며, 필름별 중성 인화 필터와 중간 회색 기준 인화 노출 정규화가 색편향·밝기를 맞추는 효과가 있다. 이 동작을 끄거나 채도를 추가해 차이를 과장하지 않는다. 네거티브에 공통 DIR coupler 계수를 쓰는 등 엔진의 근사가 있으므로, 엔진과의 일치는 실물 필름의 정확한 재현을 보증하지 않는다.

이전 STD는 33³ V-Log LUT를 사면체 보간한 결과를 다시 33³ STD 격자에 저장했다. v2는 sRGB 격자 → 선형 디코딩 → V-Gamut 변환 → 연속 엔진 → sRGB 출력을 직접 계산한다. 중간 V-Log 격자의 보간 오차가 없어지며, 최종 STD 파일의 보간 오차는 남는다. V-Log 생성 방식과 기본 선형 입력 배율 **1.0배**는 유지한다.

현재 QA의 STD 기준은 **`stdVsDirectEngine`**이다. 최종 다운로드 파일을 별도의 오프그리드 연속 엔진 계산과 비교한다. 고정 시드 random RGB 4,096개, gray ramp 129개, 5³ grid 125개, 총 **4,350개**를 사용하며 삼선형·사면체 보간을 모두 측정한다. 지표는 encoded sRGB 0–1에서 각 입력의 최대 RGB 채널 절대 오차로, 지각 ΔE나 실필름·카메라 측정치가 아니다. 이전 `stdVsContinuousComposition`은 중간 V-Log LUT를 정답으로 간주했으므로 직접 엔진 비교를 대체하지 못한다. 현재 JSON에 남겨 둔 동명의 필드는 새 STD와 이전 V-Log LUT 합성 경로의 차이를 보는 진단값이며, `stdVsContinuousCompositionPurpose`에 그 용도를 구분한다. 직접 엔진 비교도 같은 물리 모델을 별도 입력점에서 실행하는 검사이지, 독립적인 실물 필름 검증은 아니다.

upstream sRGB LUT의 `stops_above_midgray=auto`는 입력 배율 2.88배(약 +1.53 EV)이다. 현재는 기존 1.0배를 유지하고 UI에 **STD 근사 · 기본 노출**을 명시한다. 카메라 Standard의 비공개 톤·색·노출 처리를 역산하지 않았으므로 배율 선택은 여전히 근사이며, 이번 변경으로 카메라 보정이 완료된 것은 아니다. 제작 정보에서 두 배율의 차이와 적용한 설정을 확인할 수 있다.

전체 재생성을 완료했다. 네거티브 128개와 직접 스캔 4개, 총 **132개 조합 모두 ready**이며 실패·검토 경고는 0개다. **VLOG 132개는 v1과 바이트가 같고 STD 132개는 모두 갱신**됐다. 132개 ZIP·792개 미리보기도 새 STD를 반영했다. 빌드 후 264개 LUT와 1,452개 참조 자산의 크기·해시·구조 검사를 통과했다. Python **35개**, JavaScript **6개** 테스트가 통과했다.

4종 필름 × 2종 인화지 × 사용자 사진 2장의 각 4,096픽셀을 독립 colour-science 변환·직접 엔진 기준과 비교한 결과는 다음과 같다. 아래 RGB 오차는 **0–255 기준**이며 위 카탈로그 지표의 0–1 단위와 구분한다.

| 지표 | v1 | 직접 생성 v2 |
|---|---:|---:|
| 조건별 평균 채널 오차 | 0.271–0.603 | 0.074–0.101 |
| 조건별 99백분위 최대 채널 오차 | 1.402–3.312 | 0.428–0.634 |
| 전체 평균 채널 오차 | 0.434960 | 0.088743 |

전체 평균 오차는 **79.6% 감소**했다. 이는 엔진 계산 근사 오차의 감소이며 실물 필름 재현 정확도가 79.6% 개선됐다는 뜻은 아니다. 동일 Endura의 Portra400/Gold200 차이는 놀이터 1.142→1.177(직접 엔진 1.187), 실내 0.746→0.810(직접 엔진 0.825)로 직접 엔진에 가까워졌다. 필름 간 큰 색 차이가 새로 생기는 수정은 아니다.

전체 132개 조합의 사면체 STD 직접 엔진 QA에서 가장 큰 p99는 **0.004222**, 가장 큰 최대 오차는 **0.012080**이었다(0–1 단위, 서로 다른 조합). 브라우저에서 새 직접 엔진 QA 표시, C200 인화지 변경, 슬라이드 인화지 비활성화, 새 C200 STD 다운로드와 원본 파일의 바이트 일치를 확인했다. 최신 조합별 수치는 `qa.json` 및 카탈로그 `qa.stdVsDirectEngine`에 있다. 아래 슬라이드 지원·초기 구현의 수치와 실행 기록은 **v1 당시 이력**이며 v2 검사 결과로 재사용하지 않는다.

## 수치 검사

각 조합에서 고정 시드 random RGB 4,096개, gray ramp 129개, 5³ grid 125개(총 4,350개)를 검사한다. 오차는 encoded sRGB 0–1에서 RGB 채널 절댓값 오차의 최댓값이며 perceptual ΔE가 아니다. 삼선형/사면체 보간을 모두 측정한다. 카메라의 실제 보간법은 확인되지 않았다.

| V-Log LUT ↔ 직접 엔진 | 0.003994 | 0.028817 | 0.261145 |
| STD LUT ↔ 연속 합성 | 0.001201 | 0.006981 | 0.015236 |

## 미리보기

첫 버전은 scikit-image의 공개 sRGB 샘플을 사용했다. 당시 128개 조합의 LUT/미리보기 해시는 모두 달랐으나, 커피 사진에서 Portra Endura를 고정하고 다른 필름을 Portra 400과 비교하면 평균 RGB 절댓값 차이가 8비트 기준 약 2.2–7.1이었다. 이는 이 사진의 수치이며 보편적인 지각 차이를 뜻하지 않는다.

사용자 요청에 따라 다음 Standard 촬영본으로 교체했다.

| 표시 이름 | 원본 | 확인 |
|---|---|---|
| 피규어와 컬러 | PANA8578.JPG | DC-S1M2, Standard or Custom, sRGB, LUT1/2 강도 0 |
| 피규어 클로즈업 | PANA8619.JPG | 동일 |
| 장비 선반 | P1458338.JPG (`STD_source.JPG` 보관본) | 동일 |

기존 작업의 `lut-1`–`lut-5.JPG`는 EXIF에 Cloud LUT가 이미 적용되어 있어 이번 샘플에서 제외했다. 각 원본 SHA-256, 선별 EXIF, 축소 과정은 `assets/samples/manifest.json`에 기록했다. 원본은 그대로 두고 1024px로 축소한 무손실 WebP를 준비했으며 sRGB ICC를 유지하고 EXIF는 공개 이미지에서 제거했다. 색이나 노출은 별도로 수정하지 않았다. 테스트 차트는 합성 sRGB 입력이라고 구분한다.

**표시되는 원본 RGB → 최종 다운로드용 STD `.cube` 직접 사면체 보간 → WebP quality 90** 경로로 512개 미리보기를 다시 생성했다. 추가 sRGB 디코딩/V-Log 인코딩은 하지 않는다. 출력 형식 선택은 다운로드에만 적용되며 화면에 STD 미리보기임을 명시했다. 원본 전체 보기 버튼도 추가했다.

256개 VLOG/STD LUT의 SHA-256은 이전 배포와 전부 동일하다. 새 샘플로 룩을 과장하거나 LUT를 바꾸지 않았다. 모든 샘플에서 128개 조합의 미리보기 해시가 서로 다르다. 독립 colour-science reader/사면체 보간으로 2개 조합 × 3장 결과를 다시 계산해 웹 미리보기와 대조하는 6개 검사를 추가했다. 추가 2개 검사는 카메라 설정·준비 이미지 해시와 전체 조합의 미리보기 구분을 확인한다.

- V-Log 전체 임의 RGB 도메인에서는 p99 최댓값0.102048, 최대오차0.465042로 더 크다. 90개 중81개가 V-Log p99>0.05 경고를 포함하며, 숨기지 않고 QA 및 UI에 실험용으로 표시한다. STD 경고는0개다. 이 도메인의 많은 값은 F-Gamut 밖의 음수 반사율로 변환되므로 F-Log2 코드0에서 제한한다. 실제 촬영 사진의 오류 비율로 해석하지 않는다.
- 브라우저에서 공식 단독/인화 전환, Classic Neg.와 Portra Endura/실내 샘플 선택, 사용자 사진 업로드 처리, 실사 참고색 모드로 전환 시 업로드 유지 확인.
- 독립 LUT reader를 사용한 놀이터·실내 비교표: `artifacts/fuji-comparison/`. 공식 단독, Crystal Archive, Portra Endura를 같은 STD 원본에서 비교한다.

상세 계약과 출처는 [공식 FUJIFILM LUT 기록](fujifilm-official.md)에 있다. 공식 LUT 출처와 Film Lab의 입력 근사·가상 프린터 계수를 구분하며, 실물 인화나 GFX 카메라 색의 계측 일치를 주장하지 않는다.

배포 크기 조정: 최초 아카이브 258.99 MiB가 256 MiB 제한에 걸려 새 후지 샘플 미리보기 540개를 브라우저 직접 렌더링으로 전환했다. 로컬 생성/QA 자산은 유지하며, 배포 카탈로그에 `previewMode: runtime-std`를 명시한다. 공식 90개 조합은 검증된 STD LUT와 기존 원본 샘플에서 PNG 미리보기를 만들고, 기존 152개 조합은 정적 미리보기를 유지한다. 최종 자산 검사 대상은 484개 LUT, 2122개 파일 참조다.
